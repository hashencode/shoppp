# 脚手架实例化检查清单

从 `codex-admin-quick-start` 创建业务项目后，先完成本清单，再开始页面迁移或新业务开发。
本清单只用于核对，不授权自动改写未知业务配置。

## 项目身份

- [ ] `package.json` 的 `name` 已改为新项目名称。
- [ ] README、`AGENTS.md`、项目记忆中的项目名称和用途已核对。
- [ ] 页面标题、应用名称、favicon、logo 与品牌资源已替换或明确保留。
- [ ] 不再出现其他业务项目名称、域名或部署路径。

## 浏览器与本地存储

- [ ] token、用户信息、主题、列表偏好等 storage/cookie key 使用新项目命名空间。
- [ ] 旧项目遗留 key 的迁移或清理策略已明确，未在不知情时共享登录态。
- [ ] 本地 mock、测试账号和浏览器状态文件未包含真实凭据。

## 环境与接口

- [ ] development/test/production 环境变量名称、默认值和部署注入方式已确认。
- [ ] 开发环境同源 `/api` 与 dev proxy 指向正确后端。
- [ ] 示例 API、mock endpoint、固定域名和来源项目 header 已删除或明确标注为示例。
- [ ] 上传、下载、鉴权和业务 API 均由当前项目 adapter 提供。

## 路由、菜单与权限

- [ ] `routes.config.ts` 只包含当前项目需要的路由与菜单。
- [ ] `permissions.ts` 的权限键、角色和按钮职责来自当前业务权威，不从脚手架示例推断。
- [ ] 公开入口、登录回跳、basename 和部署子路径已验证。
- [ ] 示例页面是否保留已有明确结论；删除示例不影响共享 recipe 和测试资产。

## 验证

- [ ] `rg` 检查旧项目名、域名、storage key、endpoint 和品牌资源无意外残留。
- [ ] `bun run typecheck`、`bun run test`、`bun run build:test` 通过。
- [ ] 至少人工打开登录入口和一个标准页面，核对标题、品牌、路由、主题和浏览器存储。
- [ ] 检查结果记录在项目计划、初始化 issue 或交付说明中。
