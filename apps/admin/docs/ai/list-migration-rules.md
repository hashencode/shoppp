# 查询列表迁移作战手册

## 1. 文档定位

### 1.1 文档目标
在“旧项目 -> 当前项目”迁移周期内，将本手册作为所有查询列表页迁移的统一执行规则。

### 1.2 适用范围
- 页面类型：查询列表页（主）+ 表单页（辅）
- 技术基线：React + TypeScript + Ant Design + `template-kit`
- 使用时效：迁移期规则，可与长期骨架规范并行使用

### 1.3 与长期骨架规范的关系
- 本文用于“旧页迁新页”的执行规则。
- 若是新增标准页面、同构复制标准页，或要判断能否进入第一期标准骨架，优先阅读 `docs/ai/page-guardrail-recipes.md`。
- 若迁移页已经完成旧逻辑对齐，且结构满足标准列表页条件，应优先改造成 `StandardListPageRecipe` 接入，而不是继续保留散装页面骨架。

## 2. 迁移总原则（强约束）
1. 展示层：以当前项目页面规范为准（布局、组件、交互骨架、状态反馈）。
2. 业务层：沿用旧项目已验证逻辑（接口语义、权限语义、参数语义、提交与校验语义）。
3. 判断优先级：当“新展示”和“旧逻辑”冲突时，优先保留旧逻辑正确性，再在新页面规范内完成表达。

## 3. 迁移结论（先看这 6 条）
1. 列表页应先对齐模板骨架，再补业务差异。
2. 迁移目标不是“看起来像”，而是“行为一致”。
3. 查询触发、分页、按钮可见性、错误处理都要对齐旧项目。
4. 权限判断要分层：路由权限与按钮权限不要混用。
5. 每次迁移都要做“旧项目 vs 新项目”同账号对比。
6. 每页至少做 2 组账号对比（有写权限账号 / 只读账号）。

## 4. 关键实现策略（通用）

### 4.1 API 与环境
- 先迁移 API contract（入参 / 出参 / 业务码）。
- 封装旧系统兼容 envelope 的解包逻辑。
- 明确“操作成功判定口径”，并在 API 适配层固化。

### 4.2 认证与会话
- 迁移涉及登录态时，先确认 token / cookie / header 的写入时机。
- 若按钮权限来源于菜单或接口返回，必须确认加载顺序与缓存策略。
- 401/业务鉴权失败要统一处理。

### 4.3 权限模型
- 页面访问：`PermissionKey`
- 操作按钮：旧页若有细粒度权限码，新页需分层保留
- 不要把按钮权限和 role 粗暴合并成单一判断

### 4.4 页面实现策略
- 标准列表页按 `list-query-standard` 落地：
- 筛选区：查询条件 + 查询 / 重置
- 内容区：表格 + 工具栏 + 分页
- 反馈区：`loading / empty / error / partial`
- 权限区：新增 / 编辑 / 删除 / 查看等动作分层控制
- 默认交互：筛选变更不自动请求，仅点击“查询”触发（重置除外）

## 5. 标准迁移流程

### 阶段 A：准备
1. 明确旧页面路由、接口、权限点、账号样本。
2. 在新项目完成 route + permission 占位。
3. 明确“新展示 + 旧逻辑”边界清单。

### 阶段 B：接口与类型
1. 先迁 API contract。
2. 明确成功判定口径。
3. 补齐错误映射与异常路径。

### 阶段 C：页面骨架
1. 先搭模板骨架（筛选区、内容区、反馈区、权限区）。
2. 保持查询触发策略与分页策略和旧项目一致。
3. 最后再做字段、样式细节与文案微调。
4. 筛选字段优先用 `input / select / date`，仅在无法表达时再用 `custom`。

### 阶段 D：权限闭环
1. 路由权限先通。
2. 按钮权限逐项对照旧页。
3. 用“有权限账号 + 无权限账号”双账号对比。

### 阶段 E：联调与验收
1. 同环境、同账号、同操作路径，对比旧新行为一致性。
2. 记录差异并分类：功能缺失 / 权限错误 / 样式偏差 / 交互偏差。
3. 修复后回归测试，直到对比清单通过。

## 6. 统一规则与红线

### 6.1 迁移期统一规则
1. 页面骨架统一：筛选区 + 内容区 + 状态反馈区 + 权限区。
2. 查询触发统一：筛选变化不自动请求，点击“查询”才请求（重置除外）。
3. 分页实现统一：标准查询列表页必须复用 `useStandardPagination`，禁止在业务页散装维护分页状态。
4. 权限统一：路由看 `PermissionKey`，按钮权限按旧页语义分层保留。
5. 对比统一：每页至少做 2 组账号对比。
6. 验收统一：以“新页面承载旧逻辑”为通过标准，不以像素完全一致为目标。
7. 操作列宽度禁止运行时动态推算，必须在开发阶段按按钮文案和数量一次性计算后写成固定值。
8. 列表右侧工具能力（刷新 / 密度 / 列设置）若旧页存在，新页应优先同构保留。
9. 列设置渲染统一：列设置面板统一由 `ListToolbarActions` 内部渲染，页面仅传 `columnSettingOptions + selectedColumnKeys + onSelectedColumnKeysChange`，禁止页面内重复手写 `Checkbox.Group`。
10. 筛选下拉超长文案统一策略：当筛选 `Select` 选项存在超过10个字的文案时，模板层自动设置 `popupMatchSelectWidth=300`；若页面显式传入该属性，则以页面配置为准。
11. 标准列表页的 Excel 导出、Excel 批量导入和导入模板下载优先使用 `ListExcelActions` 承载 UI；导出和模板下载的 `onClick` 若返回 Promise，按钮 loading 由组件自动托管，页面仅在需要外部联动时显式传 `loading`。接口路径、鉴权、请求参数、`responseType: 'blob'` 和成功/失败提示仍放在页面所属 API/业务层。不要把 `ListExcelActions` 用到表单字段上传、视频/富文本/OSS/SDK 上传、行内单条记录动作或只有静态模板链接的页面。
12. 静态 OSS 模板/文件链接若需要通过前端 blob 下载工具包装下载，必须把原始静态链接作为 `fallbackUrl`；跨域 fetch、CORS 或签名限制导致 blob 读取失败时，应回退到直链打开。后端同源 blob 下载接口不适用此规则。
13. 标准筛选区动作顺序统一为“搜索设置 → 重置 → 查询”；搜索设置按钮必须是表单内安全按钮，不得触发表单提交。
14. 列表卡片右侧动作顺序统一为“业务动作 → 条件分隔线 → 刷新 → 密度 → 列设置”；刷新使用图标加“刷新”文本，只有前方确实存在可见业务动作时才显示分隔线。
15. `StandardListPageRecipe` 自动继承上述列表控制合同；使用 `toolbarExtra` 时页面层必须先完成权限与可见性判断，并同步声明 `toolbarExtraVisible`，禁止由 Recipe 猜测 ReactNode 的最终渲染结果。直接组合 `TemplateListFilterForm` / `ListToolbarActions` 的复杂整页必须显式设置搜索动作位置；弹窗内局部列表不强制接入页面级控制区合同。

### 6.2 不要再踩的红线
1. 不要先写页面再补权限，权限必须同步设计。
2. 不要在按钮权限上混入拍脑袋 role 判断。
3. 不要跳过“同账号旧新对比”。
4. 不要忽略失败路径；只跑 happy path 的迁移不算完成。
5. 不要把旧页明确存在的工具栏、分页、操作列语义在迁移中无依据删掉。

### 6.3 迁移防复发门禁（新增，强制）
1. 文案对齐门禁（必须）
- 迁移前先输出“旧页固定文案清单”：页面主标题、内容区标题、主按钮文案、关键状态文案。
- 迁移后逐项对齐；若有改动，必须在实现说明中写明“改动原因 + 业务确认人”。
- 未确认前禁止 AI 自创替代文案。

2. 操作列宽门禁（必须）
- 操作列宽度必须按“按钮文案字数”计算，不允许按按钮数量粗估。
- 公式：`sum(每个按钮汉字数 * 14px) + 分隔占位 + 额外余量(默认16px)`。
- 代码中必须保留固定宽度常量与注释（写明计算过程）；禁止运行时动态测量。

3. 标题层级门禁（必须）
- 迁移页的 `PageHeader` 文案默认沿用旧页；若旧页已有稳定文案，不得擅自改名。
- 多卡片页面必须说明每张 Card 是否需要标题；旧页有分区标题时，新页默认保留。
- 禁止出现“上层标题变更 + 子区块标题缺失”导致的信息层级漂移。

4. 提交前自检门禁（必须）
- 提交前必须完成以下 4 项自检并记录结果：
- 文案一致性（旧页 vs 新页）
- 操作列宽计算注释完整性
- 标题层级一致性（页头/卡片）
- 权限与路由参数一致性（含只读/编辑）

## 7. 常见问题与修复方向
1. 页面样式与模板页不一致。
- 修复：先回归模板骨架，再做业务差异微调。

2. 接口成功但列表数据不对。
- 修复：优先核对枚举值域、搜索参数名、响应解包逻辑。

3. 筛选区字段文案缺失或布局错乱。
- 修复：优先使用 `TemplateListFilterForm` 内置字段类型，避免滥用 `custom`。

4. 列表内容区接法错误导致表格不显示。
- 修复：优先同构复制标准列表页接法，再替换业务字段。

5. 工具栏能力迁移不完整。
- 修复：把刷新 / 密度 / 列设置纳入列表迁移验收清单。
- 修复：列设置面板必须走 `ListToolbarActions` 标准接口，优先复用 `buildListToolbarColumnSettingOptions(columns)`，禁止回退到页面内手写 `Checkbox.Group`。
- 修复：核对搜索设置、重置、查询的顺序，以及业务动作、条件分隔线、刷新、密度、列设置的顺序；权限隐藏业务动作后不得残留分隔线。

6. Excel 导入导出 UI 漂移。
- 修复：标准列表页若有 Excel 导出、Excel 批量导入或导入模板下载，优先复用 `ListExcelActions`，不要在页面里重复手写 toolbar 按钮、导入 Modal 和 `Upload.Dragger` 结构。
- 修复：“下载模板/下载导入模板”按钮保持 `type="link"`、无 icon，并紧跟对应导入按钮右侧；导入弹窗内只放上传相关内容，不放模板下载入口。
- 修复：`ListExcelActions` 只适用于列表批量 Excel 流程，不适用于表单字段上传、视频上传、富文本上传、OSS/SDK 上传、行内单记录动作或复杂上传状态机。
- 修复：静态 OSS 模板/文件链接若接入 `downloadBlob` 等前端 blob 下载工具，必须配置 `fallbackUrl` 为原始链接，避免 CORS 下 blob 失败后没有直链兜底。

## 8. 验收清单
- [ ] 列表首屏加载行为与旧页一致
- [ ] 筛选变更不自动请求，点击“查询”才请求
- [ ] 重置能恢复默认筛选状态
- [ ] 新增 / 编辑 / 查看跳转与旧页一致
- [ ] 错误态、空态、部分成功态反馈完整
- [ ] 权限按钮在同账号下与旧页一致
- [ ] 操作列宽度已按固定口径计算并固化
- [ ] 若旧页存在工具栏能力，新页已同构保留
- [ ] 搜索设置位于重置/查询之前，刷新显示文本，业务动作与列表工具之间的分隔线只在业务动作可见时出现
- [ ] Excel 导入导出页面已复用 `ListExcelActions` 或说明不能复用的业务原因；模板下载按钮不在导入弹窗内
- [ ] 静态 OSS 模板/文件链接若通过前端 blob 下载工具包装，已配置原始链接作为 `fallbackUrl`
- [ ] 至少完成 2 组账号对比

## 9. 红线
1. 未做旧新对照就直接报迁移完成。
2. 用模板默认行为替代旧页已定义业务逻辑。
3. 仅以“页面能展示”作为通过标准。
