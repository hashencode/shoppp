# List Column Width Rules

适用范围：后台列表页的操作列和关键标识列。

## 1. Core Rule

操作列宽度必须在开发阶段按“同一时刻可见的按钮集合”计算，并写成固定常量。禁止依赖运行时测量撑开列宽。

使用“更多”聚合时，只计算直出的可见动作；折叠菜单中的动作不计入直出宽度。

## 2. Calculation

默认口径：

- 每个中文字符按 `14px`
- 2 字按钮按 `28px`
- 4 字按钮按 `56px`
- 相邻按钮分隔占位按 `13px`
- 额外余量默认 `16px`
- 常规上限默认 `220px`

公式：

```text
sum(buttonTextWidth) + dividerGap * (visibleButtonCount - 1) + 16
```

示例：

- `查看`：`28 + 16 = 44`
- `编辑 + 删除`：`28 * 2 + 13 + 16 = 85`
- `查看 + 编辑 + 删除`：`28 * 3 + 13 * 2 + 16 = 126`
- `查看权限 + 编辑 + 删除`：`56 + 28 + 28 + 13 * 2 + 16 = 154`

## 3. Code Requirements

- 常量命名建议：`ACTION_COLUMN_WIDTH`
- 常量上方写明计算过程
- 注释中的计算结果必须与常量一致
- 互斥动作只计算同一分支可同时出现的一组
- 权限放开时可能同时出现的动作必须纳入计算
- 所有可见操作项默认直出，不再用“更多”菜单压缩操作列宽度

## 4. Recipe Helper

recipe 内部会暴露 `resolveActionColumnWidth(baseWidth, maxWidth?)`，用于按表格密度微调基础宽度。

业务页仍需要先给出正确的 `baseWidth`，不要把宽度计算责任推给运行时。

## 5. Audit Workflow

修改或新增表格列宽前，先运行静态审计：

```bash
bun run qa:table-widths
```

审计报告用于快速发现：

- 缺少 `width` 的高置信列定义
- 缺少 `scroll.x` 的 `Table`
- 已知列宽总和大于当前 `scroll.x` 的表格
- 使用动态列或无法解析宽度的人工复核项

静态审计只负责发现问题，不自动修复代码。模板仓库只沉淀通用检查口径；具体业务项目仍应结合真实接口数据和页面视觉复核固化最终列宽。

默认命令为非阻断报告模式，适合在已有历史表格的仓库中先落地工作流。若后续要接入 CI 阻断，可使用：

```bash
bun run qa:table-widths -- --strict
```
