# 右 Drawer 表单布局规范

本文承接 `ai-rules.md` 第 3.1 节，仅定义内容空间判断。业务字段、校验、提交、reset 和关闭合同以当前页面权威为准。

## 1. 基线

所有右 Drawer 固定 `size={720}`，仅支持不小于 720px 的桌面窗口。标题、滚动 body 和 footer 由 Drawer 提供；不通过加宽容器、运行时测宽或新增字段配置体系解决拥挤。

默认单列，最多两列独立字段。先判断业务关系，再看真实内容与可用空间；字段数量、控件类型、只读状态和单次测量都不是布局依据。

## 2. 布局判断

先将多行文本、富文本、上传、动态列表和表格作为全宽区域；其内部记录仍按自身业务布局。其余字段先检查关联组合资格，再检查普通双列，否则单列。

| 类型 | 条件 | 空间分配 |
| --- | --- | --- |
| 普通双列 | 同组的两个独立字段适合并排阅读/录入，标签、常见较长值和错误提示均可读 | 每字段区域默认 320px、间距 16px，常规内容区基线 656px；不足时按 DOM 顺序拆行 |
| 关联组合行 | 同一记录、复合值或一次选择中的直接对应关系，且至少一侧确实紧凑 | 紧凑侧按内容定宽，主要名称/选择占剩余空间；整体不足时在原记录内拆行 |
| 全宽区域 | 连续阅读或复杂输入，例如备注、富文本、上传、表格 | 区域占满一行；内部表格局部滚动，不让 body 横向溢出 |

320px 是标签、控件和提示的完整字段区域基线，不是每个输入控件的最小宽度。只有两个字段均有短内容依据并经验证时，才采用更小局部空间；不能用空值或“数字/下拉”类型证明可用。

关联组合必须同时满足：同行有助核对同一记录；至少一侧值域与操作紧凑；主要内容能辨认并取得完整值；标签、单位、按钮、错误不挤压邻项；不足时按原顺序拆行且不拆散对应关系。两个长名称或自由文本不能只因属于同一区块就套紧凑组合。

长名称、地址与完整标识优先更多空间或全宽，但不是无条件拆行。readonly 使用同样内容判断；静态键值可用 `Descriptions`，完整标识/长内容需要整行时检查实际占列和前项，不能只增加 span 即认定完成。

## 3. 调整和验收

1. 查看字段含义、业务边界、选项及真实或代表性内容；不擅自增加 max/maxLength。
2. 优先调整紧凑侧及外层区域，让主要内容得到剩余空间；仅缩小控件而保留均分列不会释放空间。
3. 必要时将排序、删除等记录操作移到该记录内的独立行，保留可操作尺寸。允许标签和错误在所属区域换行。
4. 仍不足时拆行或全宽；表格在自身区域滚动、图片沿用放大能力。不隐藏校验、不缩小字号。
5. 在不小于 720px 的桌面窗口验证代表性长名称、完整编号、较大数字/单位、选项、校验提示及回填。footer 可达，body 无横向溢出，字段和记录可读；空值、短占位、class 或无溢出不能替代阅读验收。

数字控件可从 120–160px 尝试，但最终按内容验证；这些尺寸与局部实测均不升级为全局阈值。常见较长值应可读，偶发超长可合理换行或沿用完整值查看。

无真实数据时注明样本与未覆盖分支。审查区分实际阻碍、优化建议和待验证，不为未来假设增加通用布局机制。
