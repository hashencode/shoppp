## Shell 加载、失败与销毁链

1. `FashionStoreShell.vue:54` 调用 `useFashionStoreVisualRuntime`。mounted 后 nextTick、`document.fonts.ready`，判定 reduced-motion。普通模式顺序注入本地 `upstream/js/jquery.js`、`upstream/js/vendors.min.js`；reduced-motion 直接以空 runtime 初始化静态能力。
2. `runtime/loader.client.ts` 使用 `new URL(..., import.meta.url)` 提供构建资源路径。每个 script 有 load/error/disposed settling；lifecycle ownNode 记录 script，加载前后扫描新增 Window property，卸载/失败时移除可配置的新 property。该扫描不是 vendor 对 document/window 注册事件的逐项销毁证明。
3. `runtime/capabilities.ts` 先移除 `.grid-loading`、解隐 `[data-anime]`，注册桌面 nav hover，设置 sticky/body runtime 标记。普通模式对**整个 document** 的 `.grid` 创建 Isotope masonry，对 Tooltip 标记创建实例；滚动监听更新进度和 sticky footer 遮挡。reduced-motion 在这些库调用之前 return。
4. 加载失败走静态初始化并写 `data-fashion-store-visual-runtime=fallback`；没有通过隐藏首屏掩盖失败。此源码分支不构成实际失败路径验证。
5. `runtime/lifecycle.ts` 倒序清理、重复 destroy 幂等、继续运行其余 cleanup 后再抛首个错误。显式登记的 Isotope.destroy、Tooltip.dispose、scroll/hover listener、style/body 标记和 script 节点可追溯。包内 data-api/auto-init 是下一表单独的能力，不能以清理 script 或 Window 变量宣称已全部消除。
6. Header 的 SearchOverlay/MiniCart 保留现有互斥与路由 closeTransient。SearchOverlay 的 focus timeout/document keydown 在卸载清理；MiniCart 使用权威 cart 状态。迁移范围不授权重建整页 focus manager。

## 网格判断输入

Isotope 的选择器是精确 `.grid`，不是所有包含 grid 字样的 class。显式候选区域有 fixture Home best-sellers/featured/magazine，Shop、Product related、Wishlist、Magazine、Article related，以及 live Home 商品区、LiveCatalog、LiveContent recovery。

`integration.css:467–497` 已将 fixture Home 第 4/8/10 区域设为 CSS Grid，隐藏 grid-sizer，并约束 grid-item 的定位；后续断点改列数。该文件开头还将 `[data-fashion-store-shop] .shop-wrapper` 设为 Flex 并隐藏 grid-sizer。这是先验证 CSS 等价的具体依据，尚不足以证明所有页面可删除 masonry。商品等高、文章不等高、筛选后、图片加载慢/失败、阅读顺序要分区域对照。Isotope 目前没有登记动态列表 watcher/arrange 或 imagesLoaded 链，不能虚构其动态排序能力。

## 网络与业务职责的源码边界

- 普通动态视觉 runtime 的明确本地脚本请求是 jquery/vendors；reduced-motion 源码分支不请求它们。完整页面网络、压缩传输、缓存和外部域名尚不能由源码阅读得出。
- `S/app/features/checkout/TurnstileChallenge.vue` 使用 `useHead` 请求 `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit`，100ms 轮询最多 50 次，成功 render widget，卸载清 poll timer/remove widget。`FashionStoreCheckoutPage.vue` 的 live/required/sitekey 条件决定组件是否出现。此服务保留，不能作为一般静态 CDN 删除。
- Checkout 的 shippingSequence、地址 fingerprint 和 debounce 是并发业务保护；返回新 Cart 通过原 ports 更新权威状态。支付目的地与跳转也由原 checkout 结果决定。依赖精简不修改安全检查、CSP、金额/库存或真实交易职责。
- fixture Home/表单通过 preview intent，其他 fixture 页面保持其已有本地适配边界；不会因抽取数量/金额展示就获得真实交易能力。

本文没有安装包、运行测试或采集浏览器证据，因此不附带通过结论，也不为只读清单添加镜像单元测试。
