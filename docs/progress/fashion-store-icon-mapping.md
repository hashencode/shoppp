# Fashion Store icon mapping — FS-R1-U2

This evidence accompanies the active [FS-R1 plan](../plans/2026-09-03-1750-refactor-fashion-store-components-dependencies-plan.md). It records migration scope and allowed glyph differences; execution status remains in that plan.

## Rendering and ownership

`FashionStoreIcon` accepts a typed semantic `name` and optional `filled` boolean. Ordinary icons are individual named imports from the already-approved `@lucide/vue` package, listed in `icons/ui.ts`. The root remains an `i` with `data-fashion-store-icon` so existing component `i` geometry selectors continue to apply. It contains one SVG, uses the inherited text color and size, and has no old icon-font class or pseudo-glyph. SVGs are decorative; existing button/link labels and accessible names remain the authority. The three Header dropdown triggers already used their `i` as a focusable button; those consumers explicitly retain an exposed root and receive a local menu-toggle name, while their inner SVG remains hidden. The component adds no interaction or announcement behavior.

Existing layout/spacing/color/size classes are retained at each consumer. The default SVG frame is 1em square, line-height 1 and baseline offset -0.125em. The original `fs-*`, `icon-small`, `icon-large` and other sizing utilities remain active. Scoped or integration styles may preserve existing control geometry. No upstream snapshot is edited.

`fixtures/home.ts` service metadata now uses typed `icon` semantics instead of `iconClass`; live service tuples and article shares pass typed names directly. Rating distributions explicitly use `filled` for selected stars, and review like glyphs retain their previous filled/outline distinction. Existing disabled and hover behavior stays on the original control.

## Exact brand source

The six retained marks are Facebook, Dribbble, Twitter, Instagram, LinkedIn and Behance. `icons/brands.ts` contains their exact SVG viewBoxes and paths from [Font Awesome Free 6.5.1](https://github.com/FortAwesome/Font-Awesome/tree/6.5.1/svgs/brands), matching the version identified in the inherited icon font CSS. The full [upstream license](https://github.com/FortAwesome/Font-Awesome/blob/6.5.1/LICENSE.txt) is retained at `icons/FONT-AWESOME-LICENSE.txt`; the paths also carry attribution. Brand logos remain those brands, including the inherited Twitter bird. The Header's former Feather Instagram outline now uses the same accurate Instagram brand asset as Footer/Shell/shares. No icon font or full brand package is added to the runtime.

## Consumer mapping

Allowed differences below concern glyph design only. They do not authorize changed content, responsive layout, control hit area or lost states. Ordinary Lucide strokes are consistently 2px in a 24px SVG viewBox; legacy filled Font Awesome arrows become outline Lucide arrows, Bootstrap short arrows become full Lucide arrows, line-font service art becomes the corresponding Lucide outline, and stars/hearts use Lucide geometry with the original fill state. Brand path design is preserved; normalized SVG framing may differ from legacy font sidebearings. Breadcrumb and coupon pseudo-glyphs become real decorative SVGs; category separator dots remain visible text.

## Retained static evidence

- A search over the Fashion Store application `components/` and `fixtures/` found no remaining `icon-feather`, `fa-*`, `bi-*`, `ti-*`, `line-icon-*` or `iconClass` references after migration. The only native `i` element is the shared icon root.
- The two font CSS application entries and the actual breadcrumb/coupon/category pseudo-element consumers are handled in the coordinated U2 integration change. Original source-contract asset inventory remains reference provenance, not a runtime load instruction.
- Browser/build/typecheck and region comparison results are recorded by the coordinated U2 verification; this mapping alone does not assert those checks passed or replace the active plan's completion criteria.
