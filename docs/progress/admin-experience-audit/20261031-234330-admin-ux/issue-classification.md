# 25项发现的UI、UX与功能逻辑分类

原有“UX-”是稳定发现编号，不代表每条都是UX问题。以下按问题性质分组，保留原编号和P1/P2/P3优先级；分类与严重程度分别判断。功能逻辑包含前端状态、校验、路由和接口集成，不能据此推定为后端业务错误。是否需要写代码也不是UI与逻辑的划分标准。

本次分类补充日期为2026-11-02，依据2026-10-31至11-01的现场证据；没有重新验证当前版本是否已修复。四组互斥计数，交叉项单列；分类不改变原先的证据强度与覆盖限制。

## 使用分类时的边界

- UI组主要调整表达和信息层级；改善UI也可能需要前端实现，不能用“改不改代码”区分。
- UX组主要调整任务和反馈；如涉及必填项、审批或发布前提，先核对业务合同，再确定改动。
- 交叉组需要明确行为验收：目标页、同步字段、对象身份、错误归因、下载结果或返回/离开状态。已确认的是行为缺口或状态不一致，具体根因和责任层仍需实现前核对。
- 待诊断组拆开处理：已确认的提示/引导问题可以作为UX事项，功能失败另查环境、数据和业务规则；不能只改提示就宣告业务闭环通过。
- 原来的P1/P2/P3用于影响排序，证据类型用于确认强度，本文件的分组用于问题性质；三者各自保留。
- 截图、复现步骤和验收要求继续引用[原图文报告](report.html)和[Markdown报告](report.md)，没有新增或重编号发现。
