# 开店指南维护说明

功能及交付权威：`docs/plans/2026-09-03-1445-feat-admin-store-setup-guide-plan.md`。

## 使用方式

有 `settings.read` 权限的管理员从后台根路径进入 `/welcome`。六个步骤可以自由进入，各步骤链接到现有业务页面；保存设置后返回指南会重新检查。旧 `/settings/launch` 地址继续提供商业设置。

自动检查与人工任务分别呈现。通过数的分母是 contracts 中的固定检查集合；无法检查和无权检查不会从分母删除。六个步骤始终展示并可分别展开，不保存任何“已上线”或人工验收状态。

## 检查口径

| 领域 | 服务端依据 | 范围限制 |
| --- | --- | --- |
| 联系方式 | 已保存配置记录及现有邮箱 schema | 默认值不表示管理员已经确认 |
| 商品 | 默认币种下已发布商品、active SKU、有效价格及可用库存 | 至少一个可售 SKU，不保证所有商品或所有币种 |
| 配送 | 有效区域、国家、方式及所选方式与各国家的区域关联 | 不证明所有重量和币种均可报价 |
| 支付 | 服务端凭证格式与环境支付模式要求 | 不连接支付商，不证明收款或回调成功 |
| 政策 | 既有政策确认、链接格式及生产占位域名检查 | 正文准确性需要人工确认 |
| 复核 | 超卖、预留时长、Turnstile 与备份配置 | 配置存在不代表实际作业已经成功运行 |

管理员仍需在现有主题流程检查店面、品牌与政策正文，并人工核验完整购物流程。指南不会创建支付或触发生产发布。自动全绿不替代 REL/DC/PG 的正式发布证据。

## 结果与恢复

- `passed`：当前配置上下文中的检查通过。
- `needs_action`：检查确认了需要处理的问题，按步骤入口修正。
- `unavailable`：配置或领域查询失败；重新检查，持续失败时由维护者排查对应 API/数据库。
- `restricted`：当前账户缺少领域读取权限；由具备相应权限的人检查。

摘要携带检查时间、环境、配置保存时间及默认币种，响应禁止共享缓存。每次检查使用同一份配置；重新检查期间旧的通过数不作为当前结果。领域失败不会抹掉独立领域的结果；配置读取失败时不会拼接默认值或历史结果。

支付与 Turnstile 密钥、备份凭证和绑定由部署维护者按现有环境配置流程处理。摘要仅返回问题代码，不返回密钥。商业设置页面不能通过修改客户端的凭证标志来改变服务端事实。运行健康单独加载，其成功或失败不计入准备进度。

## 扩展检查

1. 在 `packages/contracts/src/platform.ts` 的固定集合中定义稳定 ID 与所属步骤，明确通过口径和最小读取权限。
2. 在 `apps/api/src/settings/setup-guide.ts` 使用同一次配置输入，复用权威业务判断；查询失败返回无法检查，权限不足时不执行领域查询。
3. 在 Admin 指南中补充中英文检查名称、原因文案及处理入口。未知原因必须保留通用待处理提示。
4. 补充对应 Workers 边界测试、contract 完整性测试和必要的页面测试。变更默认入口或返回旅程时补充浏览器证据。

不要保存推导的通过率、复制商业配置、推断生产主题，或把检查规则加入结账/发布门禁。改变这些边界需要单独的产品范围与计划。

## 部署后的验证

后续按既有发布流程部署时，由部署维护者在首个验证窗口内使用对应环境账号打开指南，确认检查时间、环境和默认币种，并实际保存一项允许修改的配置后返回重查。对只读账号确认无保存操作；对没有设置权限的账号确认原业务首页仍可进入。

查看 `/admin/settings/setup-guide` 的请求错误及耗时，关联响应的 `requestId`；关注大量 `unavailable`、反复 401/403 或与当前配置不一致的结果。预期结果是完整的固定检查集合、无凭证内容和正确的缓存头。遇到持续异常时先排查配置读取/领域数据源及会话权限；若确认为本次变更回归，按现有部署回退流程恢复上一版本。不要为恢复指南而扩大权限或绕过正式发布门禁。
